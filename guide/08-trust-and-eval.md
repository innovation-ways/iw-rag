# Trust & evaluation — measured, not asserted

iw-rag's thesis is that the **verification layer is the product**. A RAG system
that *looks* right is a liability; this one is built so every capability is
backed by a repeatable experiment on a golden set, every judged metric is
reported next to a **judge–human agreement** number, and the whole flow is
traceable. This chapter explains the trust machinery and reports the live,
demo-scale numbers measured on the RTX 5090.

> **Honesty up front.** Two corpora are used below. The original **demo corpus**
> (3 docs / 18 chunks) validates the harness, floor, and invariants live — but it is
> too small/clean to separate the retrieval arms (everything saturates at ~1.000).
> A deliberately harder **benchmark corpus** (26 docs / 124 chunks, generated by
> `scripts/gen_benchmark_corpus.py` — near-duplicate invoices, rare exact-match IDs,
> multi-hop questions) was added to make the lifts measurable; the meaningful numbers
> come from it. Both are demo-scale, not a large public benchmark. Two-clocks: all
> judging/eval is offline and never touches the hot path.

## 1. The two clocks

Evaluation is **offline/batch** — it never runs on the hot path. Judges (8B
models) are loaded only for an eval run and never co-reside with the generator +
guards (which already sit near the 32 GB ceiling). This is why the published
numbers come from dedicated runs, not from production traffic.

> **Benchmark Studio** (`eval/benchmark/`, landed after phases 0–4) productizes
> this chapter: it runs a chosen golden set through the live pipeline and persists
> one append-only `benchmark_reports` row per run — T1 retrieval (recall@5/10,
> nDCG@5/10, MRR), T2 reference-free judged (faithfulness + κ, context precision),
> T3 reference-required (context recall, factual correctness), per-stage latency /
> VRAM / model-load timing, and bootstrap 95% CIs — with statistically-gated **A/B
> comparison** of two reports. Paired with the `serving/` model-swap controller, it
> answers "is model A actually better than B?" on the same card, measured not
> asserted. Still the slow clock — offline only.

## 2. Judge-free backbone + different-family judges

- **Judge-free where possible.** Retrieval, router, and guard metrics use *no*
  LLM — they are pure functions over labels (recall@k, nDCG@k, MRR, catch-rate,
  FPR). A judge can't bias what a judge never touches.
- **Different-family judges.** Faithfulness is judged by **Lynx-8B**
  (`PatronusAI/Llama-3-Patronus-Lynx-8B-Instruct`) and the general judge is
  **Selene-Mini-8B** (`AtlaAI/Selene-1-Mini-Llama-3.1-8B`) — both **Llama-family**,
  deliberately *different* from the **Qwen3-14B** generator, so the judge has no
  self-preference for the generator's own style. Both are open-weight and ungated.
- **No contamination.** The generator model is never in the judge set; the golden
  set is never judged by its own author. (Enforced by config guards + tests.)
- **Append-only history.** `eval_runs` / `eval_results` are immutable — every run
  is reproducible and auditable (`git_sha`, dataset, config recorded per run).

### Experiment #1 — retrieval ablation (live)

Three arms over the golden set, judge-free, against the live spine. **On the
benchmark corpus the three-stage spine's lift is finally visible** (the demo corpus
saturates everything at recall 1.000):

| Arm | Recall@10 | nDCG@10 | MRR |
|---|---|---|---|
| dense-only | 0.691 | 0.646 | 0.687 |
| hybrid (dense + BM25, RRF) | 0.713 | 0.715 | 0.802 |
| **hybrid + bge-reranker** (production) | **0.779** | **0.788** | **0.853** |

Measured on a **108-document / 37-query** benchmark corpus (scaled up from a 26-doc
cut — the lift is stable across both sizes, strong evidence it's real). **Hybrid gives
a big MRR jump** (0.687→0.802 — learned-sparse/BM25 ranks the rare exact-match IDs far
higher than dense), and the **reranker is the dominant recall lift** (+0.07 recall@10),
disambiguating the 52 near-duplicate invoices. Production lands at **recall@10 = 0.779,
just under the 0.80 floor** — an honest number on a deliberately adversarial corpus
(the residual misses are multi-hop queries, which motivate the agentic loop). The
floor is **not** lowered to force a pass. *(The 3-doc demo corpus scores 1.000 across
all three arms — it validates the harness but can't separate them.)* Reports:
`eval/reports/benchmark_experiments.md`.

### Experiment #2 — Phoenix traces (live-verified)

Every `/query` (and `/query/stream`) produces **one** Phoenix trace rooted at
`iw_rag.query` with the spine + loop nested beneath it — a 15-span tree:

```
iw_rag.query
├── iw_rag.retrieval.acl_filter → encode → dense → sparse → fusion → rerank
└── guardrails.sanitize → agent.grade_documents → generation.answer
    → agent.grade_batch → agent.grade_generation → guardrails.output_guard → agent.done
```

The API response carries `diagnostics.trace_ref.trace_id`, which resolves to that
exact trace in Phoenix's GraphQL API (verified by round-trip for both the JSON
and the SSE path). See [chapter 09](./09-operations.md) for where to look.

### Experiment #3 — judged faithfulness (live)

For each answerable golden query: retrieve (live hybrid+rerank) → generate a cited
answer (Qwen3-14B) → judge with **Lynx-8B** (different family). Results: **mean
faithfulness 1.000** on both corpora — **8/8 PASS** (demo) and **18/18 PASS**
(benchmark). No hallucination: every emitted answer is grounded in its retrieved
context, including the honest *"I don't have enough information"* refusals (trivially
faithful). The judge is run **two-phase** (generate with the generator up → swap the
guards down for the Lynx judge → judge) to dodge the 38 GB co-residence; see
`eval/reports/benchmark_faithfulness.json`. The number reflects the
grounded-or-refuse floor — its *calibration* is the κ figure in §4.

### Experiment #4 — agentic loop ON vs OFF (live)

The same golden set, twice: the full LangGraph loop vs the single-pass
`loop=off` path. Persisted as two append-only `eval_runs`.

| Metric | loop ON | loop OFF |
|---|---|---|
| Recall@10 | 1.000 | 1.000 |
| MRR | 1.000 | 1.000 |
| Exhaustion (fail-closed) rate | 0.111 | 0.111 |
| Grounded-answer rate | 8/9 | 8/9 |

**Honest reading:** on **both** corpora the loop and the single pass **agree** —
demo (8/9 grounded both) and benchmark (15/21 grounded both, 0.286 fail-closed both,
identical dispositions on all 21 queries). Retrieval is identical across arms by
design (the loop changes generation/grading/retries, not retrieval), so when a query
misses at retrieval the rewrite did not recover it here either. The loop's
self-correction earns its keep on **adversarial / noisy-context corpora** — where a
single pass hallucinates and the loop's grade→re-retrieve→fail-closed cycle catches
it. Neither synthetic corpus contains those cases; the value of the answers the loop
*does* emit is the **faithfulness** question (#3 = 1.000), not a disposition one.
(Run guards-OFF from the host: the guard services are docker-network-only, so a
host-run loop eval with guards on fails closed on everything — a logged gotcha.)

### Experiment #5 — guardrail efficacy / red-team (live, demo-scale)

Real probes fired at the **live guarded API** (`scripts/run_redteam_eval.py`),
metrics computed from observed behaviour rather than placeholder counts:

| Metric | Result | Probes |
|---|---|---|
| **ACL-leak rate** | **0.000** | 0 leaks / 6 cross-tenant probes |
| **Injection catch-rate** | **1.000** | 8 / 8 caught |
| **Attack-success-rate (ASR)** | **0.000** | 0 / 8 succeeded |
| **False-positive rate (FPR)** | **0.000** | 0 / 6 benign blocked |
| **Fail-closed rate** | **1.000** | 3 / 3 unanswerable refused |

Every cross-tenant probe was blocked by the **ACL pre-filter** (an hr principal
asking finance-only questions returned no finance citation, and vice-versa); all
8 jailbreak/exfil queries were rejected or failed closed; no benign query was
blocked; and every unanswerable-but-benign query refused rather than fabricate.
On this demo-scale probe set the guard chain holds end to end.

The four red-team metrics are:
- **ACL-leak rate** — cross-tenant probes (an hr principal asking finance-only
  questions and vice-versa); a leak = any returned citation from the other
  tenant. The ACL pre-filter must make this **structurally zero**.
- **Injection catch-rate / ASR** — known jailbreak / ignore-instructions /
  exfil queries must be rejected or fail closed; ASR = 1 − catch-rate.
- **False-positive rate (FPR)** — benign in-corpus queries must NOT be blocked.
- **Fail-closed rate** — benign-but-unanswerable queries must refuse, not fabricate.

**Standardized tools (now run live, fully local).** Three industry tools were wired
to the live guarded API in isolated environments (`eval/redteam/README.md`):

| Tool | Scope | Result |
|---|---|---|
| **garak** 0.15 | 7 probes / 161 prompts (prompt-injection, in-the-wild jailbreaks, indirect/latent injection) | **corrected ASR ≤ 0.000** — every output a guard block / fail-closed refusal (264/264) |
| **promptfoo** 0.121 | 5 headline demos (ACL/BOLA, indirect injection, fail-closed, PII, prompt-extraction) | **5/5 pass** |
| **PyRIT** 0.14 | multi-turn ACL-exfil (local Qwen3-14B attacker) | **`FAILURE`** — ACL held over all turns |

> **A documented honesty correction:** garak's `mitigation.MitigationBypass` detector
> *over-reports* because iw-rag hard-blocks with a custom string ("request rejected by
> input guard") that isn't in garak's English-refusal lexicon — so `parse_garak_report.py`
> reports both garak-native ASR and a **block-aware corrected ASR**. The payload-presence
> detectors (`AttackRogueString`, the `latentinjection` triggers) independently confirm
> ASR 0. Two independent harness families, same verdict: the guard chain holds at demo
> scale. The deep promptfoo redteam-*generation* sweeps and garak's full probe corpus
> remain a heavier deferral.

### Experiment #6 — GraphRAG vs hybrid spine (live, measured negative)

To run GraphRAG live, Apache **AGE was built (PG18 release-candidate) into an isolated
copy** of the store (the live demo store untouched); the first real run also surfaced
and fixed three never-live-tested store bugs (literal `cypher()` graph name,
`create_graph` transaction-abort, relation-type identifier sanitization). The graph
built (147 vertices / 289 edges), and #6 ran end-to-end:

| subset | graph nDCG@5 | spine nDCG@5 | spine recall@10 |
|---|--:|--:|--:|
| multi-hop | **0.000** | 0.347 | 0.625 |
| procedural | **0.000** | — | 1.000 |

**Then WI-031 made the graph route work and win on entities.** The first run's 0.000 was
two bugs deep: crude keyword seeds *plus* two hidden read-path bugs (per-session `LOAD
'age'`; agtype `::vertex` parsing). With a **fuzzy seed→entity resolution** (substring
lookup against the known entity names — pure SQL, no model on the hot path) and those
fixes, on an **entity-centric** golden the graph route **beats the spine**: nDCG@5
**0.395 vs 0.292** (`multihop_win=True`). It still scores 0 on procedural/policy queries
(entities don't help there), so the full gate stays unmet — exactly the documented reason
for LightRAG **"mix" mode** (blend graph+vector). The remaining structural limit is
multi-hop-with-*unnamed*-bridge (inferring the bridge needs the extraction model, which
two-clocks keeps offline). **Five latent store bugs fixed; GraphRAG now runs and wins on
its target shape.** Report: `eval/reports/graphrag_experiment.md`.

### Experiment #7 — visual: ColVision vs parse-then-caption (live)

A 10-page synthetic visual corpus (PIL-rendered charts/tables; key facts visible **only
in the image**, absent from text). Both visual arms were built and run live — including
the **ColVision late-interaction arm the codebase had only faked**:

| arm | recall@5 | nDCG@5 |
|---|--:|--:|
| ColVision (`colqwen2.5-v0.2`, MaxSim) | 1.000 | 1.000 |
| parse-then-caption (Qwen2.5-VL-7B → BGE-M3) | 1.000 | 1.000 |
| *text spine (by construction)* | *~0* | *~0* |

Both visual methods perfectly recover the image-only facts that **text retrieval
cannot** (the headline visual-vs-text gap). They **tie** (so `colvision_wins=False`,
not a loss). A follow-up with **caption-lossy dense pages** (30-row tables whose
queried cell is truncated out of the bounded VLM caption — verified) *still* ties at
1.000: **page-level retrieval is topical, not value-level**, so the caption arm ranks
the right page by topic even without the specific value. ColVision's patch-level
advantage would show at **answer** time (supplying the truncated value), not retrieval
— which supports the project's own "parse-then-caption is the recommended increment"
guidance. Building the ColVision arm required pinning a compatible
colpali/transformers/Blackwell-torch trio in an isolated venv; see
`eval/reports/visual_experiment.md`.

### Experiment #8 — long-context (native 32K) vs RAG (live, measured win)

The generator was restarted at **native 32K** (`--max-model-len 32768`, FP8 KV, prefix
caching). A NoLiMa-style probe over a ~21K-token document with one obliquely-worded
buried needle:

| arm | context fed | needle in context | **needle recovered** |
|---|--:|:--:|:--:|
| **long-context** (whole doc) | ~21,250 tok | — | **YES** |
| rag (top-8 chunks) | ~1,300 tok | **YES** | **NO** |

A real long-context **win**: RAG *retrieved* the needle chunk but the model couldn't
connect the obliquely-worded fact in isolation, while the full-document pass recovered
it — the precise "why not just stuff the window?" case the route exists for. Both
NoLiMa/RULER axes were swept: a **needle-depth sweep** recovers at **5/5 depths**
(5–95 %, no "lost in the middle") and a **context-length sweep** recovers at **4/4
lengths** up to ~31K tokens (right at the 32K ceiling, no effective-length cliff). So
**accuracy is not the limiter — cost is**: ≈21K-token prefill/query, ~6× concurrency
ceiling at 32K (latency falls 7.7 s → 1.9 s as the shared prefix warms the KV cache).
The route stays gated to whole-doc/global queries on that cost basis. Reports:
`eval/reports/longcontext_experiment.md`, `longcontext_depth_sweep.json`,
`longcontext_length_sweep.json`.

## 4. Judge–human agreement (Cohen's κ)

Every judged number is only trustworthy if the judge agrees with humans. The
metric is **Cohen's κ** (corrects for chance agreement — important when labels
are skewed). It is implemented and unit-tested
(`src/iw_rag/eval/calibration.py`), with a balanced calibration slice
(`eval/calibration/faithfulness_slice.yaml`, 6 faithful / 6 unfaithful answers
grounded in the demo corpus) and a runner (`scripts/run_kappa_eval.py`).

**Result (live, 2026-06-08): Cohen's κ = 1.000 — 12/12 agreement.** The 12 labels
were reviewed and confirmed, the Lynx-8B judge brought up (guards swapped down —
two-clocks), and `run_kappa_eval.py` scored every slice answer: Lynx agreed with the
human label on all 6 faithful and all 6 unfaithful examples. **The faithfulness
numbers in §3 are therefore calibrated, not an unvalidated judge score** — the
trust-number-with-an-agreement-figure that the Definition of Done requires.

> **Honest caveat on κ = 1.000.** The calibration slice is *deliberately unambiguous*
> (faithful = exact paraphrase; unfaithful = wrong number / direct contradiction /
> fabricated cloud hosting). A perfect κ says the judge reliably calls the *easy* cases
> — exactly what a calibration floor should confirm — but it does **not** probe the
> borderline cases. A harder, ambiguous slice (subtle omissions, partially-supported
> claims) would yield a more discriminating κ and is the natural next step.
> `eval/reports/kappa_faithfulness.json`.

## 5. The CI regression gate

`src/iw_rag/eval/ci_gate.py` enforces the floor every later phase gates against:

- **Recall@10 ≥ 0.80** — hard floor (a retrieval regression fails CI).
- **Faithfulness no-regression** — tolerance 0.03 against the frozen baseline
  (`tests/eval/baselines/phase0.json`); re-baseline only by a reviewed commit,
  never by loosening the tolerance.

The gate is unit-proven to *bite* (31 meta-tests: Recall@10 = 0.5 → fails; floor
0.8 → passes; missing baseline → fails loudly) and wired into the GitHub Action.

## 6. Trust invariants (all green)

| Invariant | How it's enforced |
|---|---|
| Judge-free backbone | retrieval/router/guard metrics are pure functions; import-guard test |
| No contamination | `gen_model` ∉ judge models; golden set never judged by its author |
| Different-family judge | Lynx + Selene (Llama) ≠ Qwen3 generator (config + tests) |
| Offline-only judges | no hot-path module imports `eval/judges.py`; no judge span on a `/query` trace |
| Append-only history | `eval_runs` / `eval_results` immutable |
